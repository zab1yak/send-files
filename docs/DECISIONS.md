# Решения

Формат: контекст → варианты → выбор → риски.

## D1. HTTP в локальной сети, а не HTTPS

**Контекст.** Телефон открывает страницу по `http://192.168.x.x:PORT`, ничего не устанавливая.
**Варианты.** (а) HTTP; (б) HTTPS с самоподписанным сертификатом; (в) локальный CA с установкой
профиля на iPhone; (г) публичный домен с сертификатом и DNS на локальный IP.
**Выбор.** (а). (б) даёт пугающее предупреждение Safari при каждом новом сертификате, (в) требует
установки и ручного доверия корневому сертификату — это опасная привычка для пользователя,
(г) требует внешней инфраструктуры и ломается без интернета.
**Риски.** Пассивный слушатель в той же сети видит файлы и ключ; активный MITM может подменить
страницу. **Меры:** только частные адреса; правило брандмауэра только для профиля «Частная»;
предупреждение в общедоступных и открытых сетях; отзыв ключей; одноразовые короткие токены.
**Что даст переход на HTTPS позже:** secure context — `crypto.subtle`, `navigator.share` с файлами,
буфер обмена, Service Worker (офлайн-PWA), защита от перехвата.

## D2. Ключ в заголовке, билеты в URL

**Контекст.** `<a href>`, `WebSocket` и `EventSource` не умеют передавать свои заголовки.
**Варианты.** (а) ключ в query; (б) cookie `HttpOnly; SameSite=Strict`; (в) ключ в заголовке +
короткие билеты в URL для WS/SSE/скачиваний.
**Выбор.** (в): ключ не попадает в URL, логи и историю. Билет — 32 случайных байта, привязан к
устройству и цели; `events` — 30 с и одноразовый, `download` — 10 мин и многоразовый (медиаплеер
iOS делает несколько Range-запросов). Отвязка устройства аннулирует его билеты.
**Риски.** Ключ в `localStorage` доступен JS страницы → главная защита — отсутствие XSS: строгий
CSP без inline, `textContent`, никаких сторонних скриптов, пользовательские файлы не отдаются inline
(кроме медиа из allowlist), на `/dl` — `CSP: sandbox`.

## D3. Ключ генерирует сервер, хранится SHA-256

Без `crypto.subtle` на телефоне генерация на сервере проще и надёжнее. Энтропия 256 бит, поэтому
медленный KDF не нужен. Сравнение — `CryptographicOperations.FixedTimeEquals`.

## D4. Код из 4 цифр — что он защищает

Защищает от гонки: кто-то сфотографировал QR и успел первым, а пользователь одобрил не тот телефон.
От активного MITM по HTTP не защищает (см. D1) — записано честно.

## D5. Целостность: CRC32 на чанк + SHA-256 на сервере

Без `crypto.subtle` клиент не посчитает SHA-256 нативно, а JS-реализация медленная на больших файлах.
CRC32 ловит повреждение чанка; сервер проверяет размер, полноту и считает SHA-256 потоково
(он идёт в историю).

## D6. Чанк 4 МиБ, выбирает сервер

Компромисс между памятью Safari и накладными расходами на запрос. Предел сервера — 16 МиБ.
Не больше 3 файлов параллельно на устройство и 8 на сервер. Уточняется замером (`PERFORMANCE.md`).

## D7. Kestrel на конкретных IP, пересоздание при смене сети

Альтернатива — `0.0.0.0` и фильтр по адресу — оставляет порт открытым на публичных и VPN-адаптерах.
Выбрано пересоздание внутреннего `WebApplication`; синглтоны (хранилища, сопряжение) переживают его.

## D8. Выбор адаптеров

Частные (RFC 1918) адреса физических Wi-Fi/Ethernet в состоянии Up; link-local — с низшим приоритетом;
со шлюзом — выше. Исключаются VPN, туннели, Hyper-V/WSL/Docker/VirtualBox/VMware и т.п. по описанию
(флаг в настройках снимает исключение). Исключение из исключения — «Мобильный хот-спот» Windows
(Wi-Fi Direct Virtual Adapter, 192.168.137.x): телефон подключается к сети самого ПК.
100.64/10 (CGNAT, Tailscale) не частный — не слушаем. IPv6 в v1 нет.

## D9. Minimal APIs, System.Text.Json source generation, JSON-файлы вместо БД

Меньше поверхности атаки, без нативных зависимостей (SQLite), путь к trimming/AOT.

## D10. Папка данных отдельно от папки Velopack

`%LOCALAPPDATA%\SendFiles.Data`, потому что `%LOCALAPPDATA%\SendFiles` принадлежит Velopack и удаляется
при деинсталляции/обновлениях. Dev-изоляция: `SENDFILES_DATA_DIR` и суффикс `-dev` (данные и
имя single-instance).

## D11. Уведомления Windows

`Microsoft.Toolkit.Uwp.Notifications` (`ToastNotificationManagerCompat`) работает в unpackaged-приложении
(AUMID и COM-активатор в HKCU). Пакет архивирован, но стабилен; Windows App SDK требует runtime —
не берём. При удалении — `ToastNotificationManagerCompat.Uninstall()`.

## D12. Трей

`H.NotifyIcon.Wpf`: WPF-меню со стилями темы. Альтернатива — `System.Windows.Forms.NotifyIcon`
(меню нельзя оформить в стиле приложения).

## D13. Брандмауэр — правило добавляет приложение

Velopack ставит без админа. При первом запуске — экран-объяснение **до** старта Kestrel (иначе Windows
покажет свой диалог, а «Отмена» в нём создаёт Block-правила, которые сильнее Allow). Кнопка «Разрешить» →
один UAC → правило только для этого exe, профиль «Частная», наш порт. Порт держим постоянным, иначе
нужен новый UAC. При удалении — попытка снять правило с UAC; при отказе правило остаётся (оно привязано
к несуществующему exe), в настройках есть кнопка «Удалить правило», в README — ручное удаление.

## D14. ZIP папок — свой потоковый writer (stored, ZIP64)

Без сжатия размер известен заранее → `Content-Length`, прогресс и Range. Совместимость с «Файлами» iOS
проверяется на устройстве.

## D15. Повторное сопряжение при смене IP

`localStorage` привязан к origin (IP+порт). Переносить ключ между origin через URL нельзя. Меры: постоянный
порт, совет про резервирование DHCP в README, быстрое повторное сопряжение.

## D16. Ссылки из присланного текста

ПК никогда не открывает их сам; кнопка «Открыть» — только для `http`/`https`.

## D17. Ограничения автопродолжения на iOS

Объект `File` переживает блокировку экрана, но не выгрузку вкладки. После выгрузки нужен повторный выбор
файла; совпадение отпечатка (`name|size|lastModified`) продолжает загрузку с места остановки.

## D18. Debug-переключатели для проверок на нейтральных данных

`SENDFILES_DEV_ADDRESS` (адрес или `none`), `SENDFILES_DEV_NAME`, `SENDFILES_DEV_THEME`, `SENDFILES_DEV_SCREENSHOT`
работают только в Debug-сборке. Скриншоты рендерятся самим WPF при 96 и 144 DPI (то же, что на экране с масштабом
100 % и 150 %), без захвата рабочего стола и без изменения настроек Windows. В режиме скриншотов сервер слушает только
127.0.0.1 — loopback не вызывает диалог брандмауэра.

**Подтверждение риска D13.** Один раз при разработке dev-сборка послушала реальный LAN-адрес. Windows сама создала
два правила **Block** (TCP и UDP, профили «Частная» и «Общедоступная») для exe из `bin\Debug` — это ровно сценарий
«Отмена/закрытие диалога → блокировка», из-за которого экран-объяснение должен идти до первого `Listen`.

## D19. Типизированный доступ к строкам

WPF компилирует XAML раньше, чем MSBuild генерирует класс из resx, поэтому `Resources/Strings.cs` написан руками.
`LocalizationTests` проверяет: ключи ru/en совпадают, у каждого ключа есть свойство, значения не пустые.
Язык меняется после перезапуска приложения.

## D20. Пульсация «Ожидание устройства…» и «ноль кадров в простое»

Пульсация — единственная постоянная анимация. Она идёт только когда её видно (окно показано, не свёрнуто, статус
«ожидание», в Windows включены анимации) и с частотой 30 кадров/с. В трее и в свёрнутом окне кадров нет.
Замер CPU — в задаче 5 (`PERFORMANCE.md`).

## D21. Скругление окна

Окно без системной рамки (`AllowsTransparency`), карточка рисуется WPF с радиусом 22 px — DWM скругляет только ~8 px.
Векторная отрисовка не обрезает углы при любом масштабе. Настоящий «continuous» (суперэллипс) вместо дуги окружности —
в задаче 5.
